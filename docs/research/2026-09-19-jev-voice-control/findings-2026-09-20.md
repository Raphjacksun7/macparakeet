## What “magic” actually is here

Jev Ultrafast’s Google Flights demo is CDP: it owns a tab, keeps a WeakMap of DOM nodes, waits for visible `[role=option]`, clicks a suggestion or calendar day, and verifies URL + field + “Select flight” independently. We cannot copy that transport. Native Accessibility is the product path.

The portable ideas are policy, not Chrome DevTools:

- Code owns URLs, form values, and app switching. Jev only picks among **enabled events** (or legality-filtered page controls).
- Consume a decision once. A transition is not verified goal success.
- Do not retry an uncertain mutation.
- Confirm only pay, delete, or send.
- One wide event per turn, with joinable per-step records.
- Situation `suggestionPicker` / `datePicker` does not enable Return. See [jev-decision-architecture.md](jev-decision-architecture.md).

## Local vs Jev split that now ships

When the next step is unique, the command router does it without a model call:

| Step | Owner |
| --- | --- |
| Activate Chrome for a web goal while another app is front | local |
| Open an allowlisted site (`web:google-flights`, YouTube, Gmail, Maps, Wikipedia, Google Search) | local; Jev never sees `role=url` targets |
| Fill origin/destination/date, press a unique city or calendar day, Escape an overlay, press Search | local `VoiceControlFlightPlan` |
| Competing unfocused city suggestions | Jev Choice over those enabled events only |
| Fill YouTube / Maps / Wikipedia / web-search boxes; press unique Gmail Compose | local |
| Exact click/type/replace/scroll/undo/keys | local |
| Unfamiliar in-page control, several similarly named results, or pay/delete/send | Jev or confirmation; overlay Jev cannot pick Return or Search |

This is the jev-ultrafast / macbrow lesson applied to AX: the model is a chooser, not a planner or a URL generator.

## Live Google Flights — what the last session actually did

Typed inbox goal: `Find one-way flights from Zurich to London on September 20 2026.`
App: Google Chrome. Observation coverage reached 73 controls on the last snapshot.

The turn **opened Flights, filled Zurich and London, committed the Zürich suggestion, typed the date, and then stalled**. It did not produce a results list.

Terminal evidence (labels only; field values were not logged):

- Last snapshot was the origin autocomplete overlay: focused `Zürich, Switzerland`, plus Zurich Airport (ZRH), Zürich HB, and Lake Zurich, Illinois.
- Last policy outcome was `duplicate_blocked` on a **key** (Escape/Return), not on a city press.
- Phase: paused. Status: “That action already ran against this interface.”

Root cause: after cities and date were filled, the origin overlay came back. `Where else?` was still in the tree, so the plan treated the form as visible and sent **Return** on the focused city suggestion. Repeating Escape against the same overlay then hit duplicate-effect protection.

A second stall class: airport names on a **results** list (`Zurich Airport (ZRH)`) were classified as a city overlay, which hid Search and Return. Classification now requires a focused suggestion or `Where else?` chrome, not merely an Airport-labeled row.

Fixture tests now cover:

- Do not Return while a city overlay is open; Escape instead.
- If Escape already ran and the overlay is still up, press `Where else?` to move focus instead of replaying Escape.
- Airport names on a results-like page are not a suggestion picker; Search remains a local press.

That is a unit fix for the recorded stall. It is **not** a live ZRH→LON results proof.

## Why native AX is harder than the demo

- Typed text ≠ selected airport. Zürich vs Zurich, overlays, and stale origin suggestions after the destination fill are all AX facts, not model facts.
- Calendar days are pressable AXButtons whose names include weekday, month, day, year, and sometimes a price. Naive `contains("20")` matches 2026.
- Snapshot-local IDs (`n:0`) collide across observations. Duplicate detection has to use semantic pre-state (role, label, value, focus), not the id.
- `AXManualAccessibility` / `AXEnhancedUserInterface` is required for Chromium webpage controls. Without it the adapter sees chrome, not the form.
- A generic interface change is a `transitionObserved` receipt. It is not “search completed.”

## Observability (wide events)

Traces used to answer “a press happened.” They now answer “which control, who chose it, why the turn stopped.”

After a turn, agents should read:

1. `/tmp/macparakeet-voice-control/latest.md` — one wide event: outcome, why, actor (`local`/`jev`), route, last control, last receipt, decision counts.
2. `latest.json` — the same summary plus joinable per-step records and offered controls.
3. `events.jsonl` — streaming `type=step` lines and one `type=turn` line when the loop stops.

Local logs may include the instruction and control labels. Copy diagnostics strips those and keeps opaque ids. Field values, selected text, audio, screenshots, credentials, and remote Jev bodies stay out.

This follows [Logging Sucks](https://loggingsucks.com): one context-rich event per request, high cardinality (task id, target id), high dimensionality (actor, route, receipt, overlay/key tokens), join by ids.
